# Features

What `agentic-os` does. Cross-platform shell, terminal, and secret-handling for every host Kai runs. Public, generic, leak-safe by construction.

This doc describes capabilities, not files. If you want a file inventory, run `ls`.

## Inventory

- [Shell and secret handling](features-shell-secrets.md) - cross-platform zsh, agent-CLI repo gate (claude/codex/opencode refuse to launch outside a git repo), in-process SSM secret loader, Warp terminal config, GPG-without-disk-passphrases, install surface.
- **Karabiner key binding assets** - `karabiner/*.json` store complex modifications symlinked into Karabiner's assets directory: Control+Escape -> backtick, a device-scoped left_option <-> left_command swap for the external keyboard, plus a command -> control remap scoped to Microsoft Remote Desktop so Cmd hotkeys reach the remote Windows session. Install `brew install --cask karabiner-elements`, setup in [docs/repo-layout.md](repo-layout.md).
- [Agents and sessions](features-agents-sessions.md) - agent self-name, session pulse, and a project-local status-line repo-checkout tracker ([`.agentic-os/statusline.sh`](../.agentic-os/statusline.sh)) that names the `org/repo` clones on disk which are not on an expected-repos list, i.e. the strays to remove.
- [Which harness when](harness-selection.md) - the five agent harnesses (Claude, Codex, OpenCode, Aider, Goose) and three model tiers (trivial-local, capable-local, cloud), with a decision guide for picking one.
- [Test harnesses](test-harness.md) - one doc per agent probing a harness+model pairing before trusting it with real work. [Agent compatibility check](agent-compat.md) runs the daily unittest smoke; Goose also ships `ward exec goose-ask`.
- [Issue-corpus discovery index](issue-corpus.md) - `ward exec render-issue-corpus` renders the Forgejo issue corpus (every repo in `scripts/issue-corpus-repos.txt`, **open AND closed**, bodies + every comment) to one markdown file per issue under `corpus/` in the private `coilysiren/inbox` (which does **double duty** as both a corpus source and the corpus output host, ward#575), so a warded container can **grep the corpus offline** to _locate_ an issue then confirm live state via `ward ops forgejo issue view`. A discovery index, not a source of truth: every file carries that disclaimer (the AGENTS.md anti-drift discipline). Incremental via `manifest.json` (skips issues whose `updated_at` is unchanged), all Forgejo I/O routes through `ward ops forgejo` (no `FORGEJO_TOKEN`), and trufflehog scans the rendered `corpus/` tree before the hourly `.forgejo/workflows/issue-corpus.yml` cron pushes it to inbox (agentic-os#297).
- [ward deployment spec bundle](ward-specs.md) - the aos-hosted `ward` deployment input bundle for the coilyco fleet, and **the source of truth** for it (aos#332). It carries the forgejo, signoz, ollama, and fleet KDL sources plus their spec locks, authored here and overlaid into ward's release, so ward can source the canonical deployment specs from this repo instead of carrying the bundle in-tree.
- [Cross-repo tooling and release](features-release-tooling.md) - pre-commit baseline, diagnostic helpers, Forgejo-canonical release actions.
- **`tooling-code-review` skill** - a one-shot code-review prompt for diff-vs-baseline review, loaded by ward's in-container review gate when it needs a hand-curated adversarial pass.
- [dev-base container image](dev-base-image.md) - the inner-loop toolchain (uv + **managed Pythons** 3.13/3.12 pre-installed under a world-writable `UV_PYTHON_INSTALL_DIR` so a non-root agent finds its repo's required Python present or downloads others on demand instead of dying with `Permission denied` at its first `uv run` ([agentic-os#327](https://forgejo.coilysiren.me/coilyco-flight-deck/agentic-os/issues/327)), pre-commit, node, go, **.NET SDK 10 + ICU** so C# mods compile in-container with full globalization rather than a per-run hand-install ([agentic-os#329](https://forgejo.coilysiren.me/coilyco-flight-deck/agentic-os/issues/329)), aws cli, claude, **mcporter**, codex, goose, docker, tailscale) plus **ward itself**, built from source at the pinned `WARD_VERSION` tag so the dev-command surface agents route through is baked in rather than `go install`-ed per run - clones anonymously (`ward` + its `cli-guard` dep are public), so no build token, and `coily` is not shipped (retired, agentic-os#261/#223) - plus the **pre-commit / CI gate tools** (golangci-lint, trufflehog, kdlfmt) so an agent self-runs `pre-commit run --all-files` and the lint/secret jobs in-container instead of hand-fetching binaries ([agentic-os#292](https://forgejo.coilysiren.me/coilyco-flight-deck/agentic-os/issues/292)) - golangci-lint + kdlfmt hand-pinned to the consuming repos' CI versions, trufflehog auto-bumped - published per release to the forgejo registry as `coilyco-flight-deck/agentic-os:<tag>`, multi-arch, pulled by tag in ward. Defaults `AWS_DEFAULT_REGION` / `AWS_REGION` to `us-east-1` and ships the `tailscale` client so a credentialed/authed container reaches SSM and the tower over the tailnet instead of failing on `NoRegion` / a missing binary ([agentic-os#286](https://forgejo.coilysiren.me/coilyco-flight-deck/agentic-os/issues/286)). Bakes a **public substrate seed** (bare mirrors of the image-tier reference repos at `/opt/substrate-seed`) so a ward container warms a cold gitcache with no network. Bakes the **in-container agent self-name** (a trimmed `agent-name.sh` under `/opt` plus a policy-tier `/etc/claude-code/managed-settings.json`) so a warded explorer / headless agent self-names like a host session, uid-independently ([agentic-os#281](https://forgejo.coilysiren.me/coilyco-flight-deck/agentic-os/issues/281)) - and appends the friendly **container name** in brackets when ward exports `WARD_CONTAINER_NAME`, self-suppressing on a native host so both stay format-consistent ([agentic-os#296](https://forgejo.coilysiren.me/coilyco-flight-deck/agentic-os/issues/296)). Points that managed `statusLine` at a baked **[status-line composer](statusline.md)** (`statusline.sh` + a `statusline.d/` provider dir) so every warded container shows the **full segment-composed line** - agent-name, repo-tracker, and any user / repo overlay provider - not just the name row, and new providers ride the next image build to all containers at once ([agentic-os#294](https://forgejo.coilysiren.me/coilyco-flight-deck/agentic-os/issues/294)). A `SessionStart` **git-identity stamp** then writes that self-name as `git config --global user.name` so a warded commit records which agent made it, leaving the load-bearing bot `user.email` ward sets at `--system` untouched for Forgejo account linking ([agentic-os#244](https://forgejo.coilysiren.me/coilyco-flight-deck/agentic-os/issues/244)). A scheduled [**auto-bump**](dev-base-auto-bump.md) (`.forgejo/workflows/dep-bump.yml`, `ward exec dep-bump`) resolves each pinned tool against upstream and commits one `ARG` bump per stale tool to main, republishing `:latest` so the image stops drifting behind upstream.
- [CI parity in dev-base](ci-in-dev-base.md) - the convention that every app's CI runs **inside the pinned dev-base image** through the same `ward exec test`/`lint`/`smoke` verbs a dispatched agent runs, so a green CI means "a headless agent can land this," not "it passed in some other environment." Pinned `vX.Y.Z`, never `:latest`, so adopting a newer image is a deliberate bump that re-validates every app. The one tag apps pin to is the aos-owned source of truth in [`docker/dev-base/ci-pinned-tag.txt`](../docker/dev-base/ci-pinned-tag.txt); an ansible/template rollout templates it into each app (authoring-vs-rollout), never fetched downward at run time. Reference: [`ci-in-dev-base-example.yml`](ci-in-dev-base-example.yml) (agentic-os#328).
- [Managed AGENTS.md pointer block](features-agents-pointer.md) - org-aware, drift-checked workspace-base pointer rendered into each repo's AGENTS.md.
- [Encoded leak guard](leak-guard.md) - pre-commit hook that rejects plaintext occurrences of awkward-leak terms (employer/partner names, private-to-public references) held as hex and decoded only in memory, so the ruleset is not itself grep-bait.
- [Context-budget report](context-budget.md) - on-demand measure of the eager startup context each harness (claude/codex/opencode) loads vs a per-harness token budget, with per-source attribution, reusing the agent-compose resolution. Ships `immediate_walk` / `peripheral_walk` primitives (tracked-file count, bytes, chars/4 token proxy over `git ls-files`) that ward's role-aware three-tier probe (ward#373) consumes for the working-dir and reference-repo tiers.
- [Mount-eligibility manifest](mount-eligibility-manifest.md) - agent-compose emits `mount-eligibility.json`: per harness, the repos it may mount on this host (`~/projects/<org>/<repo>` paths plus an always-on default set), reusing the composer's scope/harness selection so ward reads the mount decision instead of re-deriving it. Drift-checked.
- [Committed ward-ops reference](ward-ops-forgejo-reference.md) - checked-in `ward ops forgejo describe` render so operator-verb names stay greppable. `ward exec gen-ward-ops-reference` regenerates it. See agentic-os#261.
- [Catalog caps reference](catalog-caps-reference.md) - the `code-comments` / `documentation-layout` numeric caps rendered straight from the validator constants by `ward exec gen-caps-reference`, so docs and skills point at one generated source instead of hand-copying a number that drifts. `check-caps-reference-drift` fails commit on a stale render, mirroring `check-seed-skills-drift`. See agentic-os#284.
- [Tool-failure GlitchTip shipper](tool-failures-shipper.md) - `ward exec ship-tool-failures` drains the per-repo tool-use failure-record buffer (`~/.cache/agentic-os/tool-failures/<repo>.jsonl`, written by any harness producer) to GlitchTip: it gates on genuine failures (dropping classifier-`expected` benign non-zeros), sets the Sentry `fingerprint` to the record's own so a flood of identical failures collapses to one counted GlitchTip issue, tags by harness/failure_class/repo, and emits one Sentry-protocol envelope per failure past a per-file byte watermark (idempotent, resumes after a mid-file network error). The DSN is read once from SSM (`/sentry-dsn/tool-failures`, see [SSM.md](../SSM.md)) and fail-soft when absent - the buffer keeps accumulating - so the shipper lands DSN-pluggable before the GlitchTip project exists. Out-of-band (timer / SessionEnd hook), never a hot path. See agentic-os#250.
- [Canonical agent-id generator](dictatable-id-alphabet.md) - the cross-repo agent-naming primitives ward (#387) and cli-guard's Go port (#177) consume, homed in aos. [`agentic_os/agent_id.py`](../agentic_os/agent_id.py) generates a short **lowercase 2-letter+2-digit** id (`ab85`, `hj59`) over the **dictatable alphabet** (`abcdefghjkmpqrstuvwxyz456789`, confusable/homophone characters dropped), lifted from the archived o2r source not reinvented. `secrets`-backed `new_id`, a `normalize`/`is_valid` validator, and a seedable `seeded_id` that pins `agent_id_vectors.json` - the committed alphabet + seed->id contract a port asserts byte-for-byte. `org_shortnames.json` maps long Forgejo orgs to short container tokens (`coilyco-flight-deck` -> `flight`), last-`-`-segment fallback. A drift test regenerates the vector and fails CI on staleness; the doc carries a `decay-class=derived` freshness marker. `ward agent-id` prints a fresh id (`--seed`, `--org`, `--emit-vectors`). See agentic-os#302.
- [Knowledge-base freshness program](knowledge-base-freshness.md) - grades knowledge by **decay-class** (asserted/pointer/derived) and **half-life** (fast/slow), carried inline as `<!-- freshness: as-of= half-life= -->` provenance markers. `ward freshness` parses them across tracked docs and flags any fact aged past its horizon (`-- --check`), the loud trigger a scheduled probe (`.forgejo/workflows/freshness.yml`) fails on, since knowledge rot is silent where code drift is loud. Hermetic, time-based, not a commit-path hook. See agentic-os#262.
